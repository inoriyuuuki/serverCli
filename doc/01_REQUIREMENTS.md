# ServerCLI 功能需求规格

> 版本：Draft 1.0  
> 日期：2026-08-07  
> 状态：等待业务确认后进入实现

## 1. 项目目标

建设一个轻量级服务器集群控制管理系统，覆盖服务器信息展示、节点注册、能力发现、远程命令执行、关键运行数据持久化、简单账号登录和 AI Agent 临时 SSH 登录授权。

系统按环境独立部署：正式与测试数据、端口、密钥和日志不得混用。

## 2. 术语

| 术语 | 定义 |
| --- | --- |
| Control Plane / 主控服务 | 运行在主服务器的全局管理后端，负责节点、命令、任务、凭证和审计 |
| 主节点 | 环境中唯一的主服务器；同时也可运行本机 Node Agent |
| 子节点 | 主动向主控服务注册，只拥有本机视图和本机执行权限的服务器实例 |
| Node Agent | 每台服务器上的本地代理，收集状态、声明命令、执行任务和管理临时 SSH 授权 |
| Capability | 节点提供的一类功能，例如系统信息、服务管理、日志查询 |
| Command | Capability 下可调用的声明式命令，不等于任意 Shell |
| Task | 一次命令执行实例，包含参数、状态、输出、退出码和审计关联 |
| Lease | AI Agent 临时 SSH 凭证的有效租约 |

## 3. 用户与系统角色

### 3.1 管理员

- 通过 Web 登录系统。
- 主节点页面可查看和控制所有已注册节点。
- 子节点页面只可查看和控制当前节点。
- 可批准/拒绝节点注册，执行命令，查看结果，管理 AI 凭证和审计记录。
- 首版只有一个管理员账号，不提供注册、组织、多租户和复杂 RBAC。

### 3.2 主节点

- 每个环境唯一。
- 保存环境级权威数据。
- 接收节点注册、心跳、状态和命令清单。
- 调度节点命令并展示执行结果。
- 管理 AI 临时 SSH Lease 和全局审计。
- 不要求主节点故障后自动选举新主节点。

### 3.3 子节点

- 使用配置的主控地址主动申请注册。
- 获得由主节点分配的不可变 `node_id` 和节点凭证。
- 周期上报心跳、系统摘要、Agent 版本和命令清单。
- 只执行经过签名/认证、权限允许且参数校验通过的任务。
- 只能访问本机数据，不得枚举其他节点。

### 3.4 AI Agent

- 通过 API/Skill 申请指定节点的临时 SSH 权限。
- 只提交临时公钥，不获得服务器长期密码和私钥。
- 默认授权 1 小时，可按需续期，累计不超过 24 小时。
- 断开连接后主动释放；异常断线依赖连接跟踪和 TTL 自动失效。
- 所有申请、续期、登录、操作、断开、撤销和失败均需审计。

## 4. 功能需求

### 4.1 节点注册与身份

- **NODE-001**：每个环境配置唯一主服务器 IP。
- **NODE-002**：子节点首次启动时向主控后端提交注册申请。
- **NODE-003**：注册信息至少包含实例申请 ID、主机名、角色声明、Agent 版本、操作系统、架构、监听端口和本机地址列表。
- **NODE-004**：主节点为获批实例分配不可变 UUID 格式 `node_id`。
- **NODE-005**：节点身份唯一性以 `node_id` 为准；IP 只是可变化、可能重复的地址记录。
- **NODE-006**：测试环境同一物理 IP 上的主/子逻辑实例必须使用独立 state 目录、端口、密钥和 `node_id`。
- **NODE-007**：节点支持 `pending / online / degraded / offline / disabled / rejected` 状态。
- **NODE-008**：节点超过可配置心跳阈值后转为离线，恢复心跳后自动恢复在线。
- **NODE-009**：管理员可设置节点别名、标签、备注和启用状态。

### 4.2 服务器基础信息

- **INFO-001**：主界面默认展示当前访问实例对应服务器的基础信息。
- **INFO-002**：信息至少包括主机名、节点 ID、角色、IP、操作系统、架构、CPU、内存、磁盘、负载、运行时间、Agent/应用版本、最近心跳和时间同步状态。
- **INFO-003**：资源信息分“当前值”和“最近趋势摘要”；历史采样频率可配置。
- **INFO-004**：子节点只返回本机信息；主节点可按节点查看全局信息。

### 4.3 导航与可见范围

- **UI-001**：左侧导航按功能分类，建议包含概览、服务器、命令中心、任务、AI 凭证、审计日志、系统设置。
- **UI-002**：子节点隐藏集群级菜单，只显示本机概览、本机命令、本机任务、本机 AI 凭证和本机审计。
- **UI-003**：隐藏菜单不是唯一权限手段；后端必须再次校验节点范围和角色。
- **UI-004**：页面明确显示当前环境、当前节点和主/子角色，避免误操作正式环境。

### 4.4 命令发现和执行

- **CMD-001**：命令由节点本地 manifest 或插件注册，不由 Web 用户自由输入 Shell。
- **CMD-002**：命令包含唯一 ID、版本、分类、标题、说明、参数 Schema、超时、权限级别和输出类型。
- **CMD-003**：节点在注册/心跳时上报命令清单摘要；变更时上报新版本。
- **CMD-004**：主节点可按节点、分类、标签和关键词发现命令。
- **CMD-005**：执行前校验节点在线、命令版本、参数 Schema、管理员会话和权限策略。
- **CMD-006**：任务结果至少包含状态、标准输出、标准错误、退出码、开始/结束时间、耗时、执行节点和错误类型。
- **CMD-007**：支持排队、运行、成功、失败、超时、取消、节点失联和结果未知状态。
- **CMD-008**：限制输出大小，超限截断并记录；敏感信息按规则脱敏。
- **CMD-009**：首版禁止任意 Shell、未登记脚本路径和未经审核的 sudo 命令。

### 4.5 数据持久化

- **DATA-001**：正式环境使用 PostgreSQL。
- **DATA-002**：测试环境使用本地 SQLite 文件，不连接正式数据库。
- **DATA-003**：两种数据库共享同一逻辑模型和迁移版本。
- **DATA-004**：节点、心跳摘要、任务、命令快照、管理员会话、AI Lease、AI 申请记录、审计日志和清理记录写入数据库。
- **DATA-005**：高频指标不无限增长；按采样/聚合/保留策略控制容量。
- **DATA-006**：命令完整输出和 SSH 会话记录设置大小上限及独立保留策略。

### 4.6 简单账号机制

- **AUTH-001**：首版提供一个管理员账号，无公开注册入口。
- **AUTH-002**：密码使用 Argon2id 或同等级算法哈希，不可逆存储。
- **AUTH-003**：使用 HttpOnly、Secure、SameSite Cookie 会话；写操作要求 CSRF 防护。
- **AUTH-004**：支持登录、退出、会话过期、修改密码、失败限流和审计。
- **AUTH-005**：初始化密码只能通过运行时 Secret 注入，初始化完成后移除。

### 4.7 AI Agent 临时 SSH

- **LEASE-001**：AI 提交目标节点、临时 SSH 公钥、用途、请求时长和幂等键申请 Lease。
- **LEASE-002**：默认有效期为 1 小时。
- **LEASE-003**：允许自动续期，但 `expires_at` 永远不得超过 `issued_at + 24h`。
- **LEASE-004**：管理员可以关闭全局或单节点的“新申请”和“续期”。
- **LEASE-005**：管理员可以撤销单个 Lease；撤销后禁止新连接，并按配置终止现有会话。
- **LEASE-006**：AI 正常断开后，当前 Lease 自动撤销；异常断开由会话守护和 TTL 兜底。
- **LEASE-007**：到达 24 小时绝对上限后必须重新申请，不能继续续期。
- **LEASE-008**：UI 展示凭证 ID、目标节点、AI 标识、权限配置、签发/到期时间、剩余时间、续期次数、状态和最近连接。
- **LEASE-009**：UI 单独展示申请记录，包括批准、拒绝、失败和撤销原因。
- **LEASE-010**：服务器长期密码、私钥和完整 Token 不得返回给 AI 或写入数据库。
- **LEASE-011**：尽可能记录 AI 对服务器的操作；至少记录会话开始/结束、来源、远程命令、退出状态和关键文件/提权事件。

### 4.8 日志保留与清理

- **RET-001**：默认每周执行一次过期数据清理任务。
- **RET-002**：默认保留期 7 天，支持按数据类型配置。
- **RET-003**：记录可标记为 `protected/important`，自动清理必须跳过。
- **RET-004**：重要记录只能由管理员手动删除，并要求二次确认与删除原因。
- **RET-005**：清理本身必须生成不可被同批清理删除的审计记录。
- **RET-006**：自动清理支持 dry-run、删除数量上限、批量处理和失败重试。

### 4.9 一键脚本

- **OPS-001**：提供一键启动脚本，可从源码构建前后端、初始化数据库、启动服务并执行健康检查。
- **OPS-002**：提供停止、重启、状态、日志、迁移和初始化管理员脚本。
- **OPS-003**：脚本显式指定环境，默认测试环境；不得静默操作正式环境。
- **OPS-004**：正式环境启动前要求确认环境名、IP、端口和数据库类型。
- **OPS-005**：脚本不得把密码放入命令行参数、日志或 Git 文件。

## 5. 非功能需求

- **NFR-001 安全**：主子通信默认 TLS，节点凭证可轮换，所有写操作鉴权并审计。
- **NFR-002 可扩展**：新增节点和新增命令不要求修改控制面核心路由。
- **NFR-003 一致性**：同一任务只有一个权威状态；使用幂等键防止重复执行和重复签发 Lease。
- **NFR-004 可观测性**：提供健康检查、结构化日志、基础指标和关联 ID。
- **NFR-005 可靠性**：主节点短暂不可用时子节点重试，不擅自升级为主节点。
- **NFR-006 可移植**：Linux 服务器运行；源码构建过程可重复。
- **NFR-007 性能**：普通管理 API 目标 P95 小于 500ms，不包含远程命令执行时间。
- **NFR-008 时区**：数据库时间统一存 UTC，界面按浏览器时区展示。

## 6. 首版不做

- 自动选主、多主复制和主节点故障转移。
- 多管理员、多租户、组织级 RBAC。
- Web 页面输入任意 Shell。
- 浏览器内完整交互式 SSH 终端。
- Kubernetes 编排和大规模调度。
- 无限制保存完整命令输出、终端录像或高频监控指标。

## 7. 总体验收场景

1. 测试主实例和测试子实例在同一 IP、不同端口与 state 目录运行，分别获得不同 `node_id`。
2. 子实例注册后进入待审批；批准后上线并持续心跳。
3. 主界面能查看两个实例，子界面只能查看子实例。
4. 主节点发现子节点本地命令，提交合法参数后获得输出和退出码；非法参数与未登记命令被拒绝。
5. 重启服务后节点身份、任务、Lease 和审计数据仍存在。
6. AI 使用临时公钥申请 1 小时权限，登录、自动续期、正常断开撤销均符合预期。
7. 管理员禁止续期后 AI 续期失败；撤销后新连接失败，按策略终止存量会话。
8. Lease 到达 24 小时绝对上限后不能继续续期。
9. 清理任务删除过期普通记录，但保留重要记录并产生清理审计。
10. 一键脚本可在全新测试环境从源码完成初始化、启动和健康检查。
