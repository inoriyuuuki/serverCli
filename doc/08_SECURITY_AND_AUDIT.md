# 安全、Secret 与审计基线

> 日期：2026-08-07

## 1. 主要风险

- 长期 SSH 密码或私钥泄露；
- 子节点伪造身份或复制身份文件；
- 主节点对错误节点执行命令；
- Web 输入演变为任意 Shell 注入；
- AI Lease 已撤销但现有会话仍运行；
- 命令输出、终端记录或日志包含 Secret；
- 测试脚本误操作正式环境；
- SQLite/PostgreSQL 行为差异导致约束失效；
- 过期清理误删重要记录或删除审计证据。

## 2. Secret 分类

| Secret | 保存位置 | 禁止事项 |
| --- | --- | --- |
| 管理员初始密码 | 部署时临时 Secret | 不写 `.env.example`、日志或数据库明文 |
| 管理员密码 | 数据库 Argon2id 哈希 | 不可解密存储 |
| 节点凭证 | 节点 0600 state；服务端哈希/公钥 | 不跨节点复用 |
| 数据库密码 | 正式环境 Secret 文件/管理服务 | 不写仓库和启动参数 |
| TLS 私钥 | root/服务账号受限文件 | 不由 Web API 返回 |
| AI 临时私钥 | AI 客户端临时内存/受限文件 | 绝不上传 ServerCLI |
| AI 临时公钥 | Lease 数据与节点授权文件 | 到期及时删除 |
| 会话/续期 Token | 客户端安全存储，服务端哈希 | 日志只留前缀/指纹 |

用户已提供的 SSH 登录密码不得复制到任何仓库文件。建议在首次部署后轮换，并迁移到 SSH Key。

## 3. Web 安全

- 正式环境强制 HTTPS 和 HSTS。
- Cookie 使用 `HttpOnly + Secure + SameSite`。
- 所有写请求启用 CSRF 防护。
- 设置 CSP、`X-Content-Type-Options`、`Referrer-Policy` 等安全响应头。
- 密码 Argon2id 参数应可升级。
- 登录和敏感操作设置限流与审计。
- 数据库错误、文件路径、堆栈和内部 Token 不返回浏览器。

## 4. 节点通信安全

优先级：

1. mTLS，每节点独立证书；或
2. TLS + 每节点独立随机凭证 + 请求签名；
3. 不接受只靠来源 IP 鉴权。

请求应包含时间戳、nonce/request ID、节点 ID 和签名，防止重放。凭证轮换需支持短暂双版本窗口，并记录操作。

## 5. 命令安全

- 只执行本地注册命令。
- Manifest、可执行文件目录和 sudo wrapper 由 root 拥有。
- 参数使用 Schema 和 argv 传递。
- 环境变量使用白名单；清除继承的敏感环境。
- 限制工作目录、文件路径、网络和系统调用；可逐步引入 systemd sandbox/cgroup。
- 记录 hash、命令版本、执行账号、参数脱敏摘要和结果。
- 有副作用任务使用幂等或明确标记“不可自动重试”。

## 6. AI SSH 安全

- 使用专用低权限账号。
- 临时公钥按 Lease 安装，不复用。
- 默认禁止密码登录、root 登录、端口转发、Agent 转发和 X11 转发。
- 续期不允许提权、换节点或换公钥。
- 节点本地独立执行到期清理，不能完全依赖主节点在线。
- 撤销存量会话需记录 PID/cgroup 并验证进程确实退出。
- `admin` profile 默认关闭。

## 7. 审计事件目录

### 7.1 认证

- 登录成功/失败/限流；
- 退出、会话过期和强制撤销；
- 修改密码。

### 7.2 节点

- 注册申请、批准、拒绝、领取身份；
- 心跳丢失、恢复、身份冲突；
- 禁用、凭证轮换、角色异常。

### 7.3 命令与任务

- 命令清单新增、删除、版本变化和 hash 变化；
- 任务创建、拒绝、开始、终态、取消和结果未知；
- sudo、高风险命令和输出截断/脱敏。

### 7.4 AI Lease

- 申请、审批、拒绝、签发、续期、续期拒绝；
- 登录开始、操作、断开、到期、撤销和终止会话；
- 全局/节点开关变化；
- 本地授权状态不一致。

### 7.5 数据与运维

- 配置修改；
- 数据迁移、备份、恢复；
- 自动/手动清理；
- 重要标记和手动删除；
- 服务启动、停止、升级和回滚。

## 8. 操作记录能力分级

“尽可能记录 AI 操作”分三层实现：

| 层级 | 能力 | 限制 |
| --- | --- | --- |
| L1 必须 | SSH 会话开始/结束、来源、远程命令、退出码 | 对交互式 shell 内每条命令不一定完整 |
| L2 推荐 | forced wrapper、sudo wrapper、关键文件/服务事件 | 需要统一入口和系统审计配置 |
| L3 可选 | tlog/终端录像或命令审计代理 | 存储大、可能记录 Secret，需提示和严格访问控制 |

首版至少完成 L1 + 对 sudo/系统变更的 L2。若启用录像，必须设置最大尺寸、7 天保留和敏感内容处理政策。

## 9. 日志脱敏

落盘前识别并替换：

- password/passwd/secret/token/api_key；
- Authorization、Cookie、Set-Cookie；
- 数据库连接串密码；
- PEM 私钥块；
- SSH 私钥；
- 常见云密钥格式；
- 用户配置的额外正则。

脱敏后记录 `redaction_count`，但不保留原始值。输出下载也只能下载脱敏版本，除非未来设计独立高权限安全存储。

## 10. 数据清理安全

- 每周默认运行，具体时间可配置。
- 使用 UTC 计算边界。
- `is_protected=true` 的记录永不自动删除。
- 手动删除重要记录要求二次确认、原因和审计。
- 正式清理前支持 dry-run 预览。
- 单次删除设置数量上限，分批事务执行。
- 清理程序不得使用无条件整表删除。

## 11. 正式环境保护

- UI 和 CLI 使用红色/明确文字标识正式环境。
- 远端脚本默认测试，正式必须显式参数与确认。
- 部署、迁移、重启、清理和 SSH 配置变更前备份并准备回滚。
- 正式数据库与测试数据库账号、网络和 Secret 完全隔离。
- 禁止将生产数据复制到测试环境，除非经过脱敏和明确批准。

## 12. 上线前安全门禁

- [ ] 仓库 Secret 扫描无发现。
- [ ] 正式 TLS 验证通过。
- [ ] 管理员密码哈希与会话安全测试通过。
- [ ] 节点复制凭证和重放请求被拒绝。
- [ ] 任意 Shell 与参数注入测试被拒绝。
- [ ] Lease 到期、撤销和断连后授权文件无残留。
- [ ] 撤销时活动会话按配置终止。
- [ ] 日志、输出、数据库和报告不包含 Secret。
- [ ] 清理不删除重要数据。
- [ ] PostgreSQL 备份恢复演练通过。
